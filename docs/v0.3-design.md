# v0.3 design: colored status bar, `--plain`, terminal tabs, git viewer

Status: draft for review. Scope is four user-requested features. The
constraints from CLAUDE.md still hold:
- `app.rs` stays pure.
- Manager keys are Alt-only and never collide with Claude Code.
- Protocol additions stay backward compatible.
- Secrets never go to argv or state files.
- Tests assert on the screen model.

Claude Code 2.1.280 binds these Alt keys itself: o, p, t, w, j, m, k, v (the
list was found by grepping the bundle). claudio already uses ← → n r x a s g h
q `.`. New keys: **Alt+c** opens a terminal (Alt+t is claude's thinking
toggle; the user chose Alt+c) and **Alt+l** opens the git log.

## 0. Groundwork (one small commit before the features)

- **Split `tui/ui.rs`** (1213 lines) into `tui/ui/mod.rs` (frame layout,
  tabs, pane, modal dispatch, shared helpers), `tui/ui/status.rs` (the
  two-line bottom bar) and later `tui/ui/git.rs`. This is a pure move with no
  behavior change.
- **Daemon capabilities.** Add `Welcome.features: Vec<String>`
  (`#[serde(default)]`). A new daemon advertises `proto::FEATURES =
  ["shell", "git"]`. The client remembers them per host. Before it sends
  `Spawn{kind: Shell}` or `GitLog`, the TUI checks
  `App::host_supports(host, "shell")`. When the feature is missing it shows a
  notice instead: "daemon on devbox is older: run `claudio daemon restart`
  there". An old daemon would ignore the unknown `kind` and spawn claude, so
  this check is what keeps that from happening silently.
- **Move the session-marker scrub list** (`CLAUDE_SESSION_MARKERS`) out of
  `daemon/session.rs` into `claude/mod.rs`, so `--plain` can reuse it.
- **Move proxy resolution** (`proxy_state::resolve_profile` /
  `proxy_env_for` and the default-profile choice) into `proxy/`. It has no
  dependency on the TUI, and both the TUI and `--plain` need it.

## 1. Colored bottom bar (`ui/status.rs`)

- Both lines get a dark background (`Color::Indexed(236)`) instead of
  `REVERSED`. Colored text on reversed video looks muddy and is inconsistent
  across terminals.
- **Line 1 (session):** each segment is its own span, separated by a dim ` · `:
  - location: `host:` in magenta bold for remote hosts, cwd in bold white
  - `⎇ branch` in green
  - model in bold blue
  - `ctx 143k` in cyan
  - state, in the same palette as the tab glyph (working cyan, input yellow,
    approval red, idle green, exited dim)
  - uptime, dim
  - proxy: `⇄ proxy:name` in green, or `direct` dim

  Notices replace the segments and render bold yellow (red when
  disconnected).
- **Line 2 (machine):**
  - `cpu` and `mem` labels in dim bold.
  - Sparklines are colored per bar by level: green < 60 %, yellow < 85 %,
    red above.
  - The current value is bold and colored the same way.
  - Right side: upgrade notice in cyan, then `Alt+h` bold and ` help` dim.
- Helpers are pure and unit-tested: `level_color(pct)` and `spans_sparkline`.

## 2. `claudio --plain`

`claudio --plain [--proxy NAME | --no-proxy] [claude args…]`

The word is "plain": it is plain claude. `--clean` suggests wiping state, and
`--simple` reads like a degraded mode.

- No daemon, PTY, tabs, keys or hooks. It resolves the proxy the same way the
  manager does for a new session:
  - `--proxy` / `--no-proxy`, else the `CLAUDIO_PROXY_URL` env var, else the
    default profile.
- It then:
  1. fetches `/v1/claudio/config` with a short timeout (falling back to the
     built-in defaults),
  2. builds the env with `proxy::env::session_env`,
  3. scrubs the claude session markers,
  4. `exec`s the real claude with the remaining args, so the tty, signals and
     exit code are exactly claude's.
- With no proxy configured it behaves exactly like passthrough.
- `-p` / `--print` after `--plain` is rejected with a hint, because claudio
  never runs `claude -p`. `--api` is also rejected.
- The token reaches claude only through env (exec), never argv.
- Code lives in `src/plain.rs` (about 60 lines). `main.rs` dispatches when
  `argv[1] == "--plain"`.

## 3. Terminal tabs (Alt+c)

### Protocol
- `SessionKind { Claude, Shell }`, `#[serde(default)]` = Claude.
- It is added to `SpawnSpec.kind`, `SessionInfo.kind` and the journal
  `Entry.kind`.

### Daemon
- A `Shell` session runs the user's login shell with `-l`, in `cwd`:
  - The shell is found from `$SHELL`, else the `getpwuid` shell, else
    `/bin/sh`.
  - No `--settings`, hooks or token; claude markers are scrubbed.
  - Proxy env is not injected; it is a plain terminal.
- Its state is set to `Idle` at spawn and never changes. Shells have no hooks,
  so they never ask for attention.
- The OSC title still updates the tab title (via `clean_title`).
- **Exit:** a shell closes on any exit status. A claude session closes only
  on status 0 (the clean-exit rule added in c318c7d). Bash exits with the last
  command's status, so Ctrl+D after a failing command must still close the
  tab.
- **Recovery:** after a daemon restart, a journaled shell respawns as a fresh
  shell in the same cwd. There is no resume and no resume-retry.

### TUI
- `Action::Terminal` (Alt+c): spawn `Shell` on the active session's host, in
  its cwd. The new tab goes right after the active tab, which matters when
  the active tab is itself a terminal, and becomes active. The session list
  gains an `insert_at(i)`.
- **Tab:** the glyph slot shows `$` in bold green instead of a state glyph.
  The label is `term@<host>` with the host always shown, `local` included. A
  renamed terminal keeps the `$` and the `@host`: `$ build@devbox`.
- **Status line 1 for a terminal:** `$ terminal · host:cwd · uptime`, with no
  model, ctx or proxy.
- Alt+x closes a terminal with the same confirm as claude.
- Alt+a skips terminals.
- Alt+g lists them with `$`.

## 4. Git viewer (Alt+l)

Git runs **on the session's host** through the daemon, so it works the same
for local and SSH sessions. It is read-only.

### Protocol
New request/reply ops (old daemons answer `Unknown` → error; the feature check
above shows a notice first):

```
GitLog  { cwd, all: bool, skip: u32, limit: u32 }
  → GitLog { root, head: Option<String>, commits: Vec<GitCommit>, more: bool }
GitCommit { id, short, parents: Vec<String>, author, time: i64, refs: Vec<String>, subject }

GitShow { cwd, id }
  → GitShow { id, author: String /* "name <email>" */, time: i64, committer_time: i64,
              message: String, files: Vec<GitFile>, patch: String, truncated: bool }
GitFile { path, old_path: Option<String>, added: Option<u32>, removed: Option<u32> }  // None = binary
```

### Daemon (`daemon/git.rs`, with pure parsing in `git.rs`)
- Runs `tokio::process::Command` with:
  - the env `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0` and `LC_ALL=C`,
  - `-c core.pager=cat -c color.ui=never --no-pager`,
  - `kill_on_drop`, and a 10 s timeout.
- **log:**
  ```
  git -C cwd log [--all] --no-color --format=%H%x1f%h%x1f%P%x1f%an%x1f%at%x1f%D%x1f%s%x1e --skip=N -n limit+1
  ```
  Fetching one extra commit is how `more` is set. `root` comes from
  `rev-parse --show-toplevel` and `head` from `symbolic-ref --short -q HEAD`.
- **show:** `id` must match `^[0-9a-f]{7,64}$` (this blocks argument
  injection), and is also passed after `--end-of-options`. It runs:
  - `show -s --format=…%B` for the metadata,
  - `show --format= --numstat -z -M` for the files,
  - `show --format= --patch --no-ext-diff -M` for the patch.
- **Frame limit:** the patch is truncated at a line boundary so the encoded
  reply fits in `MAX_FRAME` (1 MiB). It is capped at 384 KiB raw, and the cap
  is halved until the serialized reply fits. The reply then has
  `truncated = true`.
- Non-UTF-8 output is decoded lossily. Errors such as "not a git repository"
  come back as `Msg::Error` with git's first stderr line.

### TUI
- **State machine:** `Modal::Git(GitView)` lives in `tui/git_view.rs`, a pure
  state machine like `wizard.rs`. `on_key` / `on_mouse` return an `Outcome`:
  `None | Close | LoadMore{skip} | Show{id}`. `App` turns that into
  `self.request(host, …, ReplyTo::GitLog(gen) / ReplyTo::GitShow(gen, id))`.
  A generation counter drops stale replies (the same S7 pattern as the
  wizard).
- **Opening:** Alt+l opens the view at once with "loading…" and requests 200
  commits. When the request fails, the error shows inside the view.
- **Log page:**
  - Header: `⎇ main  ~/repo  · 1234 commits loaded · [a] all branches`.
  - Each row is `◆ a1b2c3d  subject…  (HEAD -> main, origin/main, tag: v1)  author  3h`. `◆` marks a merge and `●` a normal commit.
  - Hash in yellow. Refs: HEAD cyan bold, local branches green, remote
    branches red, tags yellow bold. Author blue, age dim. The selected row is
    reversed.
  - Keys:
    - `↑↓ j k PgUp PgDn Home End` move.
    - `Enter` or a click opens a commit.
    - `/` filters by hash, subject or author over the loaded commits.
    - `a` toggles all branches.
    - `Esc` closes.
  - More commits load as the selection nears the end.
- **Commit page:**
  - Header: hash, author, absolute and relative date, refs.
  - The message, with the subject in bold.
  - A diffstat: each file with `+N` in green, `-M` in red and a small bar.
  - The patch, colored by line kind: `diff --git` bold, `@@` cyan, `+` green,
    `-` red, context default. The kind of each line is classified once when
    the reply arrives, and only visible lines are rendered.
  - Keys:
    - `↑↓ j k PgUp PgDn Space g G` scroll; the wheel scrolls too.
    - `n` / `N` jump to the next or previous file in the patch.
    - `Esc` or `Backspace` goes back to the log, keeping the selection.
  - When `truncated` is set, a dim footer says "diff truncated (N KiB)".
- **Rendering:** `tui/ui/git.rs` uses the full pane area (not a centered
  popup), with the tab bar and status bar still visible.
- **Scope:** the keys above apply only inside the view. Global Alt keys keep
  working (Alt+q quits, Alt+←/→ switch tabs and close the view).

### Not in v1 (deliberately)
Graph lines, blame, staging/committing, a working-tree diff and side-by-side
diffs. A future `w` key could show `git diff HEAD` (uncommitted changes) on
the same commit page, since that is the same `patch` renderer.

## 5. Allow bypass-permissions mode (`--allow-dangerously-skip-permissions`)

The user wants every claude that claudio starts to accept bypass mode. Claude
has no env var or settings key for this, only the CLI flag. The flag doesn't
*start* in bypass mode; it only makes bypass mode selectable with Shift+Tab.

- **Config:** a new `[claude]` section in `config.toml` with
  `allow_skip_permissions = true` (on by default, can be turned off). It is
  read by whoever launches claude:
  - the **daemon**: from its own host's config at startup, stored in
    `daemon::Config`. Remote hosts usually have no config, so they get the
    default.
  - **`--plain`**.
- **Daemon:** `session.rs::command()` adds the flag for `Claude` sessions (not
  shells) on every launch path (new spawn, `--resume`, resume-retry). It skips
  the flag when `spec.args` already contain it or
  `--dangerously-skip-permissions`. Because it lives in `command()`, the
  journal never stores it, and recovery and resume always get it.
- **Compatibility:** an old claude without the flag would fail every spawn
  with "unknown option". The daemon detects support once, cached in a
  `OnceLock`, by checking that `claude --help` output contains the flag. This
  runs beside the existing `claude --version` probe. Unsupported claude means
  no flag.
- Passthrough (`claudio <args>`), `-p` and `--api` are unchanged.

# Review outcome: binding decisions

Reviewed by Fable 5.1 and GPT Astra. **These decisions override the sections
above wherever they disagree.**

## Protocol and compatibility
- **There is no `Welcome.features` and no `SpawnSpec.kind`.** Terminals use a
  new op instead: `Msg::SpawnShell(ShellSpec { id, cwd, name, rows, cols })`.
  An old daemon answers an unknown op with `Error "unsupported op…"`, so the
  op fails safe by construction. A single helper,
  `App::older_daemon_notice(host, err)`, maps that error, for SpawnShell and
  all git ops, to "daemon on X is older: run `claudio daemon restart`".
- **`SessionKind { Claude, Shell }`** (`#[serde(default)]` = Claude) lives on:
  - `SessionInfo` and the journal `Entry` (authoritative)
  - the TUI's `SavedSession` / `Recovered` / `SessionView`
- **Journal kind is authoritative.** When the daemon receives a `Spawn` for an
  id that its journal records as `Shell`, it starts a shell. This covers an
  old client respawning a dormant terminal. `retry_spawn_fresh` honours kind
  too.
- **Recovery:** every TUI path that rebuilds a spawn (`state.rs` respawn,
  both branches in `sessions.rs` recovery) carries `kind`. They collapse into
  one `App::send_spawn(host, SpawnRequest, proxy: Option<String>)`, which
  also owns the warm/cold proxy-config branch. Shells never get `--resume` or
  proxy env.

## Terminal tabs
- **Token:** shells keep a unique spawn token (`forget_live` and the
  clean-exit ownership guard need it) and skip only `--settings`.
- **Labels:** `label()` ignores `title` for shells, so a `PROMPT_COMMAND`
  title can't replace it. The tab renderer adds the `$` glyph and the
  `@host` suffix; `label()` itself stays bare because it feeds notices, the
  overview and the rename input.
- **Branch:** the daemon broadcasts `Meta{branch}` at spawn for both kinds.
- **Directories:** "cwd" means the launch directory. A shell's later `cd` is
  not tracked; this is documented.
- **Key shadowing:** inside terminal tabs, readline's Alt+c (capitalize) and
  Alt+l (downcase) are shadowed by claudio, as are Alt+r, n, a, s, g, h and
  q. Document this in the README.

## Modal and key routing
- **One general rule, with no git-specific case:** when a manager action
  fires while a modal is open and `modal.yields_to_actions()` is true (Git,
  Overview, Help, ProxyStats), close the modal and run the action.
  Text-input modals (Rename, Wizard, Close) keep today's behavior.
- **Mouse:** wheel and click events go to the modal when it wants them
  (Git).

## Git viewer
- **Code location:** `daemon/git.rs` holds exec and pure parsers together,
  with unit tests. Protocol types live in `proto.rs`.
- **Ops:**
  ```
  GitLog    { cwd, all, skip, limit≤500 }  → GitLog { root, head: Option<String>, commits, more }
  GitCommit { cwd, id }                    → GitCommitInfo { id, parents, author, email, time, committer_time, refs, message, files: Vec<GitFile>, first_parent: bool }
  GitDiff   { cwd, id, file: Option<u32>, path: Option<String>, old_path: Option<String> } → GitDiff { id, path, patch, truncated }
  ```
  `file` is the position in the commit's `files`. The daemon re-derives the
  exact name (any bytes) from `--numstat -z` and runs file-selecting commands
  from the repository top level, because those names are root-relative.
  `path` / `old_path` are display text and are used only without `file`.
  A log page whose first record overflows the capture is a bounded error;
  the viewer also stops paginating after a page with no new commits.
- **Commit page:** header, message, then a selectable file list with a
  colored diffstat.
  - `Enter` on a file opens that file's patch; `d` opens the whole commit
    patch.
  - In the patch view, `n` / `N` go to the next or previous file.
  - `Esc` / `Backspace` go back one level.
- **Execution never runs inline in the client loop.** Each request runs as a
  `tokio::spawn`ed task that replies through the client's queue, like
  Attach does.
  - Concurrency is bounded per client (`Semaphore(2)`).
  - The overall deadline is 10 s, below the client's 30 s request deadline,
    and git is started with `kill_on_drop`.
- **Bounded memory:** stdout is read through `take(CAP+1)` (CAP is 384 KiB
  for a patch, 256 KiB for log or meta) and stderr through `take(4096)`; the
  child is then killed and waited. Every variable field (message, subject,
  refs, paths, file count ≤ 2000) is capped. The encoded envelope is
  measured once and the patch trimmed at a line boundary to fit `MAX_FRAME`
  with slack. If the metadata alone does not fit, the reply is a bounded
  error.
- **Command:**
  - `Command::current_dir(expand_tilde(cwd))` rather than `-C`.
  - `env_remove` for `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`,
    `GIT_COMMON_DIR`, `GIT_PREFIX`, `GIT_CONFIG_PARAMETERS`, `GIT_PAGER`
    and `PAGER`.
  - Env `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`.
  - `--no-pager -c core.quotePath=false -c diff.noprefix=false -c diff.mnemonicPrefix=false -c diff.submodule=short -c log.showSignature=false -c color.ui=never`.
  - Diff-producing commands also get `--no-ext-diff --no-textconv -M`.
  - Merges use `--diff-merges=first-parent`; the header says "vs first
    parent". On git older than 2.31, fall back to `-m --first-parent`.
- **Ids:** only full hashes are accepted: `^[0-9a-f]{40}$|^[0-9a-f]{64}$`.
  Paths go after `--`.
- **Log framing:** `-z` plus `--format=%H%x00%P%x00%an%x00%at%x00%D%x00%s`,
  parsed as fixed groups of six fields. Each group is validated by checking
  that `%H` is hex, and a group that fails is skipped.
- **Sanitizing:** everything git-sourced is cleaned on the daemon:
  - C0 and C1 control characters are stripped, except `\n` in messages and
    patches.
  - Tabs are expanded.

  This blocks terminal injection from a commit subject.
- **Pagination:** offset (`--skip`). `r` refreshes, and a HEAD change between
  pages is accepted. Both are documented.
- **TUI routing:** a single `ReplyTo::Git { gen, seq }`. `GitView::on_reply`
  dispatches on the reply message; the generation drops replies for a closed
  or reopened view, and `seq` drops superseded requests. Line kinds are
  classified at render time from the first byte.
- **Layout:** `tui/git_view.rs` holds the pure state machine
  (`on_key`/`on_mouse`/`on_reply` → `GitOutcome`) and `tui/ui/git.rs`
  renders it.

## `--plain`
- **Name:** `--plain` (a flag, as the user framed it).
- **Shared resolver:** `load_proxy_profiles()` and `ProxyChoice` move into
  `proxy/` so the TUI and `--plain` share them.
- **Env:** a single shared `proxy::env::apply(&mut Command, env)` scrubs the
  session markers and removes `ANTHROPIC_API_KEY` when a token is injected.
  Both the daemon's `apply_env` and `--plain` use it.
- **Fallback:** the config fetch has a 2 s timeout. On fallback, one line goes
  to stderr.
- **Rejected:** `-p`, `--print` and `--api`.
- **Docs:** the flag is added to `cli::HELP_APPENDIX`.

## Status bar
- **Colors:** every span gets an explicit fg on an explicit bg
  (`Indexed(236)` bg, `Indexed(252)` text, `Indexed(245)` dim), so the bar
  stays readable on light themes.
- **Sparklines:** each is colored by its latest value, not per bar.
- **Truncation** is span-aware and keeps `Alt+h help` visible at 60 columns.

## Tests added by the review
- A git request does not stall a concurrent `Data` frame.
- A fixture repo with a merge, a rename, a binary file and a non-UTF-8 name.
- Truncation is measured on the encoded frame.
- A subject containing ESC is sanitized.
- A configured textconv never executes.
- A shell tab survives a daemon restart as a shell; fake claude is not
  invoked.
- A shell exiting with code 1 closes its tab.
- `--plain` puts the proxy env in place and removes `ANTHROPIC_API_KEY`, and
  `--plain -p` is rejected.
- `SpawnShell` deserializes to `Unknown` on a frozen v0.2 enum.

## 6. Keeping claude up to date (local and remote)

Requested after the review. It follows the same rules.

### Config (`[claude]` in `config.toml`)
```toml
[claude]
allow_skip_permissions = true   # §5
update_check = "ask"            # local claude vs the release channel: "ask" | "auto" | "off"
remote_check = "ask"            # remote claude vs the local version:  "ask" | "auto" | "off"
```

### Local check (TUI start, at most once a day)
- Compare the local `claude --version` with
  `https://downloads.claude.ai/claude-code-releases/<channel>`. That URL
  returns a bare version.
  - The channel is claude's own `autoUpdatesChannel` from
    `~/.claude/settings.json` (default `latest`).
  - The result is cached in `update.json` next to claudio's own check, using
    the same once-a-day rule and `CLAUDIO_NO_UPDATE_CHECK=1`.
- Versions are compared numerically (`2.1.280 < 2.1.296`).

### Remote check (when an SSH host connects)
- Compare `Welcome.host.claude.version` with the local version. The prompt
  fires when the remote version is older or missing.

### Prompt
A small generic confirm modal (`Modal::Confirm(ConfirmPrompt)`) offering:
- `[y] update`
- `[n] not now`
- `[s] skip this version` (remembered in `state.json`, per host and
  version)

| Setting | Behavior |
|---|---|
| `"auto"` | Skips the prompt and updates, with a notice. |
| `"off"` | Never checks. |

When claude is missing on a remote, the prompt offers to install it with the
official installer (`curl -fsSL https://claude.ai/install.sh | bash`), still
only after a `y`.

### Running the update
Local and remote go through the same daemon op, so the logic exists once:
- `Msg::UpdateClaude { install: bool }` → `ClaudeUpdated { version: Option<String>, ok: bool, tail: String }`.
- The daemon runs `claude update` (or the installer) as a spawned task with:
  - a 300 s timeout and `kill_on_drop`
  - output bounded to its last 4 KiB
  - session markers scrubbed
- It then re-probes `claude --version` and refreshes `HostInfo`.

Old daemons answer `unsupported op`, which maps to the "daemon is older"
notice.

### After an update
Running sessions keep their old binary. The notice says "claude updated to X
on devbox; new sessions use it". Nothing restarts automatically.

## 7. Reset the current session (Alt+e)

Alt+r, s and t are taken by claudio, and Alt+b, d, f and y by claude's
readline keys, so the key is Alt+e ("restart"). It opens a
`Modal::Confirm`-style prompt:

| Key | Action |
|---|---|
| `r` | Restart claude in the same tab and resume the same conversation. This picks up a claude update, a proxy change, or recovers a wedged process. |
| `n` | Start a new conversation in the same tab and directory. |
| `Esc` | Cancel. |

- **Protocol:** a new op, `Msg::Respawn { id, fresh: bool }`. The daemon
  kills the live process (if any) and spawns the same session id again:
  `--resume <claude_session_id>` unless `fresh`, with the journaled args and
  name. The client re-sends the proxy env, the same way `send_spawn` does.
  The journal entry and the tab are kept, and no `Removed` is sent.
- **Old daemons** answer `unsupported op`, which shows `older_daemon_notice`.
- **Terminals:** on a shell tab, Alt+e restarts the shell. The prompt for a
  shell has only `[r]`.

## 8. Which proxy credential a session uses

claude-proxy pins each conversation to one upstream credential, and Claude
Code sends `X-Claude-Code-Session-Id` on every request.

- **Proxy (Go):** remember, in memory with a bounded LRU, the last credential
  used for each `(user token, claude session id)`. Add
  `GET /v1/claudio/session?id=<claude_session_id>`, which returns
  `{credential: {label, provider, plan}, bound_at, last_seen, switched_at?,
  utilization?}`. It is scoped to the caller's token (404 for any other
  token's sessions) and is read-only.
- **claudio:**
  - Poll it for the active proxied session: on activation, then every 30 s

## 9. `--plain` keeps a few keys

The user wants Alt+h (and sensible keys such as Alt+s) in `--plain`.
`--plain` therefore becomes a single-session mode of the manager TUI instead
of an `exec`:
- There are no tab bar, status bar or wizard; the pane fills the screen.
- The session is spawned through the daemon with the proxy env and the
  claude args. It is killed when the UI exits, and the UI exits when claude
  exits, with claude's status.
- The spawn is marked `SpawnSpec.ephemeral` (`#[serde(default)]`). The daemon
  keeps such a session in memory only (never in its journal, so a restart
  forgets it) and lists it with `SessionInfo.ephemeral`; a running manager
  neither shows it as a tab nor resumes it. An older daemon ignores the flag,
  and the session then shows up in a manager as before.
- The keymap is restricted to plain-scoped bindings: Alt+h help, Alt+s proxy
  stats, Alt+l git log, Alt+e reset. Everything else goes to claude.
- `-p`, `--print` and `--api` are still rejected.
